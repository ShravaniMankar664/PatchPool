PatchPool

Fund the fix. Lock the commit. Release the reward.

An on-chain escrow and review workflow that links a software-fix bounty to a specific code submission, a human reviewer, and a recorded settlement.

PatchPool01 / 08
The problem

Funding, review, and payment lose their link

Software-fix bounties often coordinate the task, source revision, reviewer decision, and reward across different tools. Participants may struggle to see what was reviewed, who was authorized to decide, and where escrow went.

Before PatchPool

Task board → code host → informal review → separate payment

Records are fragmented, and payment conditions may be enforced manually.

PatchPool's scope

Link the funded task to a committed revision, evidence digest, reviewer decision, and settlement recipient.

PatchPool complements Git hosting and human review; it does not replace them.

Problem and intended use02 / 08
The workflow

One contract-governed bounty lifecycle

01 · SponsorCreate a task, assign reviewer, fund escrow; other sponsors may add funds.
02 · ContributorSubmit Git commit ID, evidence digest, and payout address.
03 · ReviewerOne assigned human reviews the specific submission and approves or rejects.
04 · SettlementApproved reward goes to the stored payee; release can be retried.
05 · ExpiryEach eligible contributor claims their own refund after deadline + 7 days.
The smart contract enforces escrow, address roles, and settlement. A human reviewer judges code quality.

Read path

Browser → same-origin bounded JSON-RPC proxy → MST Mainnet RPC

Proxy forwards allowlisted reads; transaction broadcast and signing methods are rejected.

Contract

Solidity 0.8.20 · OpenZeppelin ReentrancyGuard · Hardhat

Per-wallet contribution accounting, submission records, reviewer decision, payee-bound payout, individual refunds.

Evidence boundary

Task JSON is public and hash-bound. Git object ID and evidence digest identify submitted values.

Evidence files stay off-chain. A matching digest proves byte equality only—not truth or correctness.

System architecture04 / 08
Contract guarantees and limits

Rules are enforced at the address level

Enforced

  • Creator and contributors cannot submit or receive payout.
  • Reviewer cannot fund, submit, or receive payout.
  • Approval is bound to one submission ID.
  • Reentrancy-protected payout and pull refunds.
  • No refund after approval; eligible claims begin after seven days.

Not guaranteed

  • Code quality, tests, or evidence truth.
  • Distinct human identities behind addresses.
  • Reviewer impartiality; one reviewer only.
  • Quorum, arbitration, or dispute resolution.
  • Independent professional audit.
